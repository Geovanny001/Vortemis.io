## 1. Resumen ejecutivo

La jornada se centró en cuatro bloques:

1. **Estabilizar la ingesta P0** y el despliegue.
2. **Medir el motor** con un dataset público etiquetado (CICIDS2017) y documentar su calidad real.
3. **Mejorar UI/ops**: dashboard, purga administrativa, healthcheck y seguridad básica.
4. **Separar la UI del motor** mediante una capa de lectura con DTOs, puertos y servicio de consulta.

El motor funciona y está desacoplado de las presentaciones. La deuda principal ya no es de arquitectura, sino de **calidad de detección**, **portabilidad** y **operación**.

## 4. Arquitectura actual

```text
domain
  └── NetworkFlow, IPAddress, Port, Protocol, Timestamp

application
  ├── use_cases: ingesta, normalización, autoencoder, training, MITRE
  ├── queries: FlowRecord, OperatorIdentity, TelemetryReadService
  └── ports: FlowQueryPort, OperatorAuthPort, TelemetryMaintenancePort

infrastructure
  ├── persistence: PostgreSQL, SQL adapters, auth, purga
  └── zeek: parser, telemetry source, live sensor, header

entrypoints
  ├── dashboard.py  (Streamlit)
  ├── tui.py        (Textual)
  ├── cli.py
  └── container.py  (composition root)
```

La UI depende de `TelemetryReadService`, no de la base de datos. Esto permite añadir Streamlit, TUI, Flet, NiceGUI, Qt o React sin tocar el motor.

## 9. Deuda y limitaciones

### Motor/detección

- Modelo sin calibrar para tráfico real.
- Autoencoder actual con AUC 0.694 en CICIDS2017.
- Autoencoder más grande sube a 0.868, pero no es producción.
- Decisión pendiente: features de comportamiento + autoencoder grande, o híbrido supervisado.
- Regla C2 demasiado amplia; falta evaluación por táctica con tráfico real.

### Contrato de consulta

- `FlowQueryPort` no tiene filtros ni paginación; la UI filtra en pandas.
- El dashboard todavía lee el checkpoint directamente; falta `EngineMetadataPort`.
- Falta tipar errores de aplicación para las UIs.
- El servicio agrupa lectura, auth y purga; evaluar separarlo en servicios más pequeños.

### Persistencia/datos

- Deduplicación al reingerir o reiniciar el CLI.
- Sin índices en `ts`, `src_ip`, `is_anomaly`, `tactic_id`.
- Sin retención ni particionado.
- Sin Alembic.
- `dim_hosts` sigue pendiente de decisión.
- SQLite no es un perfil soportado oficialmente para desktop.

### Operación

- Rate limiter en memoria por proceso.
- TLS solo documentado, no ejecutándose.
- Sin logs estructurados, métricas ni auditoría.
- Dashboard Streamlit sin caching/fragments ni filtros SQL.
- TUI sin paridad completa con el dashboard.

### Arquitectura de presentaciones

- No se creó otro repositorio.
- Monorepo vs repo separado se decide cuando exista un frontend real.
- No hay API REST; una app React/remota requeriría un adaptador API y revisar esa decisión.
